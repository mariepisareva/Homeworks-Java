## Задание 2: результаты эксперимента

```
Operation              Elements    ArrayList, ms   LinkedList, ms
-----------------------------------------------------------------
Add to end                10000            0,672            0,331
Add to start              10000            4,588            1,194
Insert in middle          10000            3,159           45,159
Get by index              10000            0,109           42,523
Remove from start         10000            3,817            0,193
Remove from end           10000            0,188            0,261
```

Замеры: 3 прогрева, 6 измерений, в таблице медиана.

**Выводы.** Доступ по индексу показал самую большую разницу: у `ArrayList` `get(i)` это обращение к элементу массива за O(1), а у `LinkedList` для каждого индекса приходится идти по ссылкам от начала или конца списка, поэтому весь цикл занял 42,5 мс против 0,1 мс. Операции в начале списка выгодны `LinkedList`: там достаточно переставить пару ссылок за O(1), а `ArrayList` каждый раз сдвигает весь массив через `System.arraycopy` за O(n), что дало 4,6 мс и 3,8 мс против 1,2 мс и 0,2 мс. Вставка в середину у обеих структур O(n), но причины разные: `ArrayList` сдвигает половину массива одним блочным копированием, а `LinkedList` сначала ищет позицию, проходя часть списка по ссылкам. Этот поиск вместе с плохой локальностью данных (узлы разбросаны по памяти и хуже попадают в кэш процессора) сделал `LinkedList` медленнее примерно в 14 раз. Добавление в конец и удаление с конца у обеих коллекций O(1), результаты близки. Небольшое преимущество `LinkedList` при добавлении в конец может объясняться тем, что `ArrayList` периодически расширяет массив и копирует его. Различия меньше миллисекунды лежат на уровне погрешности (JIT, сборщик мусора), поэтому строгих выводов по ним делать нельзя. Итог: ни одна коллекция не лучше всегда, выбор зависит от профиля операций, но при частом доступе по индексу и вставках в середину `ArrayList` предпочтительнее.
